## 4. 三个衔接点接口契约

### 衔接点① 挂起快照 ↔ 批量审批

| 侧 | 契约 |
| --- | --- |
| v2 侧 | 挂起瞬间 `state → json.dumps → SET refund:suspend:{case_id}`（TTL 7 天）；PG checkpoint 为权威恢复源 |
| v4 侧 | 批量审批导出查 `RefundCase.status = SUSPENDED`；读 Redis 快照做展示；逐条调 `resume_workflow(case_id, action, comment)` |
| 关键约定 | `case_id` = checkpoint `thread_id`；审批动作固定枚举「同意 / 拒绝」；三层防重（幂等键 + 分布式锁 + 状态校验） |

### 衔接点② 售后三卡片 ↔ 意图识别

| 侧 | 契约 |
| --- | --- |
| v2 侧 | `POST /api/v1/cases`（multipart：order_id / applicant_amount / actual_amount / description / image），手动三卡片 |
| v4 侧 | 双层意图识别：Node A 规则（关键词）→ Node B LLM（口语化精判），判三意图 |
| 关键约定 | 识别输入 = `description` 字段；**退款 / 退货 → 走决策流，换货 → 转人工**（不涉及金额） |

### 衔接点③ 订单三查 ↔ Critic 安全

| 侧 | 契约 |
| --- | --- |
| v2 侧 | `order_verify_node` 三查：真实性（查不到→REJECT）/ 一致性 / 价格（不平→HUMAN_REVIEW）+ 顺带查订单状态防重复退款 |
| v4 侧 | Critic（description 进 LLM 前打分，≥0.85 转人工）+ DLP（进 LLM 前与写日志前脱敏）+ Tool 过滤（finalize 退款前校验） |
| 关键约定 | 合并后决策流顺序：`intake → Critic → DLP → order_verify → [fraud+sentiment 合并] → decision → finalize(Tool 过滤)` |
