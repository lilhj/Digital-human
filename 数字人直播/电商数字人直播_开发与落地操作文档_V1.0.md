## ——基于当前直播间页面 + 主流竞品技术路线的可实施方案

> 文档版本：V1.0  
> 目标：在现有“米家 / 商品 / 购物车 / 数字人直播”页面中，接入一个可以 **实时说话、实时回答、展示商品、处理弹幕、支持长期直播** 的 AI 数字人主播。

## 2.1 腾讯云路线

腾讯云公开的交互 Demo 已经验证了一个非常接近你页面的模式：

- 云端数字人渲染
- 文本或音频驱动
- WebRTC / TRTC / RTMP 视频输出
- H5 页面实时播放
- WebSocket 发送文本驱动指令
- 可以接入自己的大模型
- 直播服务支持开启/关闭直播和直播接管

官方 Demo 的 Python 依赖包括 `requests`、`websocket-client`、`pydub`，WebRTC 播放使用 H5 播放页面。官方文档还明确给出了“建流 → 查询会话状态 → 开启会话 → 驱动数字人”的流程。

**对你的项目最有价值的是：**

```text
你的后端
   ↓
创建数字人 Session
   ↓
拿到 WebRTC 播放地址
   ↓
前端 <video> / WebRTC Player
   ↓
数字人出现在你截图左侧黑色视频区域
```


例如 Xiaomi 17 Max：

```json
{

  "price": 4799,
```

# 13. 为什么一定要 WebSocket

普通 HTTP：

```text
用户
 ↓
POST
 ↓
服务器
 ↓
回答
```

直播互动更适合：

```text
浏览器 ←──────── WebSocket ────────→ 服务器
    ↑                                ↑
    │                                │
    ├── 弹幕                         ├── AI回答
    ├── 点赞                         ├── 直播事件
    ├── 商品切换                     ├── 数字人状态
    └── 用户问题                     └── 库存变化
```

这样可以实现：

- 实时弹幕
- 实时数字人状态
- 实时字幕
- 商品切换
- 主播打断
- 互动事件

# 15. 数字人打断机制

这是直播体验的关键。

必须支持：

```text
主播说话
    ↓
用户问题进入
    ↓
判断问题优先级
    ↓
停止当前播报
    ↓
回答问题
    ↓
恢复商品讲解
```

API：

```http
POST /api/live/{session_id}/interrupt
```

后端：

```python
await avatar.interrupt()
```

然后：

```python
answer = await agent.answer(user_message)

await avatar.speak(answer)
```

腾讯云的公开能力已经支持在数字人播报过程中进行打断，说明这类能力已经成为实时直播场景的重要接口设计。

# 17. 数据库设计

## live_session

```sql
CREATE TABLE live_session (
    id VARCHAR(64) PRIMARY KEY,
    room_id VARCHAR(64),
    product_id VARCHAR(64),
    avatar_provider VARCHAR(32),
    avatar_session_id VARCHAR(128),
    stream_type VARCHAR(32),
    stream_url TEXT,
    status VARCHAR(32),
    started_at DATETIME,
    stopped_at DATETIME
);
```

# 20. 延迟预算

你真正要关注的是：

```text
用户提问
 ↓
ASR / 文本
 ↓
Agent
 ↓
LLM
 ↓
TTS
 ↓
Avatar
 ↓
WebRTC
```

目标：

| 环节 | MVP目标 |
|---|---:|
| WebSocket | <100ms |
| Agent 路由 | <100ms |
| LLM 首 token | <500ms |
| TTS 首音频 | <500ms |
| Avatar 首帧 | <500~1000ms |
| 总体首响应 | 1~2秒级 |

不要一开始追求“零延迟”。

优先保证：

> **用户感觉数字人是在实时回答，而不是等很久后突然播一段视频。**

# 38. 最终结论

你的项目最合理的第一版，不是：

```text
自己训练一个数字人
+
自己训练大模型
+
自己开发 TTS
+
自己开发 WebRTC
```

而是：

```text
                    你的核心产品
                         │
       ┌─────────────────┼─────────────────┐
       │                 │                 │
   直播前端           AI Agent          商品系统
       │                 │                 │
    WebRTC          LLM + RAG          SKU/库存
       │                 │                 │
       └─────────────────┼─────────────────┘
                         │
                    Avatar API
                         │
                 腾讯 / HeyGen / Xmov
                         │
                      WebRTC
                         │
                      数字人
```

**先把“数字人 + AI 大脑 + 商品 + 弹幕 + WebRTC”这条链打通。**

然后再逐步替换：

```text
第三方 Avatar
      ↓
自研 Avatar

第三方 TTS
      ↓
自研 TTS

普通 LLM
      ↓
电商专用 Agent

单直播间
      ↓
多直播间

单机
      ↓
数字人集群
```

这样研发风险和成本都低很多，而且你的现有页面基本不用推倒重做。
